# 执行与实时字幕

先核真实设备身份/版本、音频路由/音量、当前会话和其他执行进程，告诉用户本轮范围/话术。沿用用户已授权录音；不因查看旧录音而重新启动测试。

`VQA run /local/case.yaml --mode live --config /local/config.yaml --prepared-assets /local/prepared/manifest.json --verbose`。默认产物在data_root/runs，禁止输出到源码目录。原采集/步骤/日志都会封存；`VQA watch --device-log`只跟随，不开第二个执行器。

先在当轮做一条有界输入探针，检查当前绑定trace的`voice.tts_text_changed`，要求source=worker、segment_id、明确partial/final和replace语义；同时保留设备输入识别。核对分段是否完整，不能将dynamic_current等本地欢迎语当成云端答复。验证可用时设置`asr.live:false`，继续连续录音和抓全部事件，语义复核选择server_text。

服务端文本缺失或关键段不全时，再配置`asr.live:true`、ASR解释器和模型路径。独立进程跟随WAV写`asr/live.jsonl`，包含partial/final和主机观察时间；录音结束产生`asr/transcript.json`。已有录音可单独后处理，不必为了ASR再播一次。ASR不使用设备字幕作提示，也不在播音时机循环内调用GPT。初始化失败要查解释器、依赖、模型和输入路径并修复，再对原WAV验证；不能生成占位字幕。

执行器等待本轮trace和明确条件，文件播完不等于设备收到。实体动作只在授权范围内，由用户观察；灯光/音量输入可按实际设备原路径播放，搜索/云端门不得掩盖“控制词根本未播放”。具体设备仍须核本地唤醒/输入门。

普通问答与打断后等待回复时，wait_output用after_input_final:true限定本次输入后的新回复分段。旧故事被打断后的迟到final不能充当数学新问题已答完；输入final缺失时先保留现场、排查输入和采集，再修复/补验或讨论，不继续播下一句掩盖。静音/倒计时仍只作调度代理，不能签实际音频队列已空。

搜索完成等待用role:body，等待词与明确失败说明/正文分开；“查查天气”等衔接语不能让执行器提前说再见。短普通数学答复可用role:any，不能将搜索正文长度规则机械套到“八”等短答案。worker_speaking可能跨多个句子持续true，第二次属性变化不能冒充第二句；句首候选须留分段/录音依据并披露代理限制。

失败保留首轮和一次独立诊断，按用例依赖/停止条件决定后续。环境/执行器错误先修复，再用新目录定向核验；这与无变化反复重跑设备用例不同。原生run-suite仅编排与采证，当前GPT Agent应逐用例完成review后再决定是否诊断。明确退出不能以idle_timeout替代。

## 主动排障与收口

1. 保存日志、录音、当前会话和已执行步骤，区分设备行为、执行器和环境问题。
2. 自主处理已授权范围内的可逆问题：发现本机正确工具/解释器、修复依赖与路径、准确补齐预生成音频、恢复本执行器的采集、修正等待词/回复关联和清理时机。音频路由仅在确认目标后调整；当前用户静音或有人使用设备时先沟通。不要擅自改服务器开关、重启生产服务、清数据或执行用户已跳过的断网/实体动作。
3. 用具体变更和新证据验证修复；同一原因最多两次有明确改动的环境修复，超过后整理事实和方案与用户讨论，不交未完成的最终回执。独立可测项继续，首次结果始终保留。
4. 只有实际完成核验的项才输出有问题/无问题。必需条件确实无法自补时，先提出准确缺口和可行路径，不用BLOCKED/未核验作为交付结论。将本次可复用的执行/判定修复更新到skill，真实项目记录留本地。

计时按[timing](timing.md)处理；执行结束不能只检查是否生成了文件，还要看每轮结果是否关联正确、数值能解释实际录音。

结束确认采集与房间已关闭，随后进入review；不凭execution=completed宣称通过。HTTP不自动具备本机实时ASR和联合等待能力，按接口声明处理。
