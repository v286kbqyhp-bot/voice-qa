# 常见问题与边界

- 录音ASR与设备ASR是两条链路。报告必须标清来源，不能把完整现场对话和端侧缺词混称“ASR坏了”。
- 同音词可让GPT基于上下文解释，但原转写不改，推测栏给出引用和不确定性。设备没说的答案不能根据用例预期补齐。
- 输入紧接查询、或与等待语重叠时要保存实际时机和录音；安静样本通过不能覆盖重叠失败，不能据少量样本直接归因距离或ASR模型。
- 等待词不代表检索成功。语义判定需要答案/明确失败反馈；设备ASR缺字只能提示上行/识别/门控链异常，不能证明后端已收到完整控制词。
- 云端未就绪可能让硬件命令根本未播放。用户要观察实体功能时先确保按授权实际发出原话术；是否动作由用户/传感器证据判断，不能凭回复“调好了”通过。
- worker_speaking、字幕、RMS、非静音PCM和真实物理起音不是同一事实；精确时延/重叠必须说明测量层。
- 当前trace、输入窗和字段应明确匹配。关闭事件可能无trace；不要要求不存在的字段。session_output_ready不等于首句已完整可收。
- idle_timeout不是主动退出。正常收尾不默认播取消搜索，已闭房跳过cleanup；用户停止不再自动发声。
- 实时ASR的partial会修订，final与完整JSONL保留；字幕进程失败不能洗掉原始录音，也不能假装仍在实时分析。
- GPT语义复核在调度循环外，由调用skill的Agent或明确配置的provider完成。run结束先pending，review完成再按实际标准给判断。
- 所有实测数据和摘要都留外部data_root。旧录音快捷链接仅为本机兼容，不进入Git；源码仓库/工作树备份在本机archive，删当前文件不等于重写Git历史。
- Windows需要本机Python/音频设备/ADB配置、hooks与ASR依赖验证；Mac配置和相对解释器路径不能照抄。
